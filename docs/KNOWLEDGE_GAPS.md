## KG-001：Git 工作区、暂存区与提交快照

### 来源

M0 第一次稳定提交的分步练习。

### 当前理解

已理解仓库、工作区和 `.gitignore` 的基本作用，尚未完成第一次暂存与提交检查。

### 缺少什么

需要通过实际操作理解 `git add`、`git diff --staged`、`git commit` 和 `git log` 之间的关系。

### 为什么重要

只有能检查提交快照，才能避免把无关文件、生成物或错误内容写入历史。

### 学习优先级

必须。

### 学习任务

在 M0 首次提交前后分别检查工作区、暂存区和提交历史。

### 小实验

暂存文件后比较 `git diff` 与 `git diff --staged` 的输出差异。

### 状态

学习中。

## KG-002：CMake、Ninja 与 GNU Arm 驱动链的调用关系

### 来源

M0 开发工具链梳理。

### 当前理解

CMake 生成 Ninja 规则，Ninja 执行命令，通常由 `arm-none-eabi-gcc` 驱动编译、汇编和链接，并在内部调用相关工具。

### 缺少什么

尚未从真实构建日志验证编译参数、链接脚本、启动文件和产物生成过程。

### 为什么重要

这是后续定位编译、链接和固件体积问题的基础。

### 学习优先级

应该，在 M1 学习。

### 学习任务

生成最小工程后阅读 CMake 配置和 Ninja 的详细构建命令。

### 小实验

在 M1 使用详细构建输出，辨认一次 C 编译、一次汇编、一次链接及一次 `objcopy` 命令。

### 状态

未验证。
