## KG-001：Git 工作区、暂存区与提交快照

### 来源

M0 第一次稳定提交的分步练习。

### 当前理解

已能区分工作区、暂存区和提交快照，并能根据 `git status --short`、`git diff`、`git diff --staged` 和 `git log` 判断状态。

### 缺少什么

核心概念已通过 M0 和 M1 文档提交实际验证；后续需要继续熟悉分支合并和远程分支协作。

### 为什么重要

只有能检查提交快照，才能避免把无关文件、生成物或错误内容写入历史。

### 学习优先级

当前基础已完成；后续按需巩固。

### 学习任务

后续提交继续保持“检查工作区 → 暂存 → 检查暂存快照 → 提交 → 检查历史”的流程。

### 小实验

已完成暂存前后差异比较，并观察新分支提交后 `main` 与功能分支指向不同提交。

### 状态

已掌握当前阶段所需基础。

## KG-002：CMake、Ninja 与 GNU Arm 驱动链的调用关系

### 来源

M0 开发工具链梳理。

### 当前理解

CMake 生成 Ninja 规则，Ninja 执行命令，通常由 `arm-none-eabi-gcc` 驱动编译、汇编和链接，并在内部调用相关工具。

### 缺少什么

尚未从真实构建日志验证编译参数、链接脚本、启动文件和产物生成过程。

### 为什么重要

这是后续定位编译、链接和固件体积问题的基础。

### 学习优先级

应该，在 M1 学习。

### 学习任务

生成最小工程后阅读 CMake 配置和 Ninja 的详细构建命令。

### 小实验

在 M1 使用详细构建输出，辨认一次 C 编译、一次汇编、一次链接及一次 `objcopy` 命令。

### 状态

未验证。

## KG-003：CubeMX 器件选择与 STM32F407 时钟树

### 来源

M1 最小裸机工程准备。

### 当前理解

已确认必须选择 STM32F407VGT6、LQFP-100，并已知板载 HSE 为 8 MHz、LSE 为 32.768 kHz。

### 缺少什么

尚未实际完成 CubeMX 器件选择，也未验证 RCC 时钟源、PLL 参数、总线分频和最终时钟频率。

### 为什么重要

器件或时钟树配置错误会影响引脚、链接内存布局、HAL 时基和所有外设波特率。

### 学习优先级

必须，在 M1 当前完成。

### 学习任务

先核对 CubeMX 器件与封装，再逐步配置 SWD、RCC 和 Clock Configuration，每一步单独检查。

### 小实验

生成最小工程后，通过构建结果和板上 LED/UART 行为验证系统时钟配置。

### 状态

未验证。
