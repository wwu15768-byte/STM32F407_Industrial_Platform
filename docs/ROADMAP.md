## M0：工程准备

目标：建立可复现、可追踪的工程起点。

验收标准：

- 开发工具链可用且版本有记录。
- Git 仓库根目录、提交者身份和 `main` 分支正确。
- `.gitignore` 不误伤源码和工程配置。
- README 与 docs 职责清晰、内容反映真实状态。
- 产生第一次有意义的稳定提交。
- 后续建立远程仓库并验证首次推送。

## M1：STM32 裸机稳定基线

目标：在不引入 FreeRTOS 的前提下，建立 Known Good Baseline。

计划验证：系统时钟、基础 GPIO、UART 调试输出以及下载运行流程。具体引脚、时钟源和开发板连接必须确认后再配置。

## M2—M4：RTOS 与并发基础

- M2：FreeRTOS 启动、Task、调度、优先级、阻塞与栈。
- M3：UART 日志、错误码、调试宏和线程安全输出策略。
- M4：Queue、Task Notification、Mutex、Ring Buffer、所有权和生产者/消费者模型。

## M5—M9：采集与设备通信

- M5：传感器驱动、采集任务、数据队列和处理任务。
- M6：UART DMA、IDLE、变长帧和异常接收。
- M7：RS485 物理层、半双工及 DE/RE 时序。
- M8：Modbus RTU 帧、CRC、超时、异常帧和基础寄存器模型。
- M9：统一数据结构、有效性、时间与设备信息、必要的数据封装。

## M10—M12：系统集成与收尾

- M10：打通通信、Node-RED 和 InfluxDB 基础数据链路。
- M11：长时间运行、压力、故障恢复和系统联调。
- M12：完成架构图、数据流图、开发与测试记录、演示和项目总结。
